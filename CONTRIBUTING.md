# Contributing

Thank you for your interest in contributing to an Advantec Global Services project. This document covers the basics that apply across our repositories; individual repositories may add their own guidance in a local `CONTRIBUTING.md`, which takes precedence.

## Before you start

- Check existing issues and pull requests to avoid duplicating work.
- For anything beyond a small fix, open an issue first so we can discuss the approach before you invest time in it.
- Security issues are handled separately — see our [security policy](SECURITY.md) and do not open public issues for them.

## Making changes

1. Fork the repository and create a branch from `main`.
2. Keep changes focused. One concern per pull request.
3. Match the style and conventions of the surrounding code.
4. Add or update tests where the repository has them, and make sure the existing suite passes.
5. Update documentation affected by your change.

## Pull requests

- Write a clear title and description: what changed, and why.
- Link the related issue if one exists.
- Be responsive to review feedback. We aim to review pull requests promptly, and small, well-scoped changes get merged fastest.

## Commit messages

- Use the imperative mood in the subject line ("Add retry logic", not "Added retry logic").
- Keep the subject under 72 characters; use the body to explain the why when it is not obvious.

## Questions

If you are unsure about anything, open an issue and ask. See [SUPPORT.md](SUPPORT.md) for other ways to reach us.
